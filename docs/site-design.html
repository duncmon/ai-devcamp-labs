Site Design Choices, Navigation Philosophy & Dual-Track IA

An architectural rationale documenting how this repository presents two distinct visitor trips — the upstream instructor curriculum and Duncan's verified engineering portfolio — connected through a non-intrusive 1-click companion bridge.

1. The Problem: Two Incompatible Visitor Journeys

In many coding workshops, attendee repositories face a common information architecture dilemma:

  • The Upstream Narrative: Authored by the workshop instructor (Sonika Janagill), it is pedagogical, prescriptive, and linear. It guides students through intentional stumbling blocks and starter code conventions.
  • The Attendee Engineering Portfolio: Authored by the attendee (Duncan Moncrieff), it is critical, empirical, and architectural. It documents 7 custom Architectural Decision Records (ADRs), resolves production gotchas, audits telemetry traces, and implements production-grade security safeguards.

Attempting to merge both narratives into a single page or blending them together creates cognitive friction. A reader trying to follow the tutorial gets lost in advanced post-mortems; an engineer reviewing the production architecture gets bogged down in beginner codelab steps.

2. The "Two Visitor Trips" Philosophy

The core design principle adopted for this site is uncompromised immersion with instant cross-branch mobility:

Trip A
The Instructor Workshop Track
Preserves the original GDG London DevCamp curriculum, codelabs, setup guides, and starter architecture blueprints in their authentic form under docs/instructor/.
Trip B
The Attendee Engineering Portfolio
Provides a rigorous, fully verified engineering walkthrough with 85+ authentic trace figures, 7 ADRs, and 27 empirical post-mortems under docs/.

Rather than displaying side-by-side dual-column text (which cramps readable code blocks and diagrams), each reading page remains 100% focused on its respective track.

3. The Split-Gateway Portal (The Landing Experience)

The repository root page (docs/index.html) implements the Split-Gateway Portal based directly on attendee whiteboard conceptual sketches:

  • Deliberate User Choice: Visitors are immediately presented with two prominent doors ("Instructor Track" vs. "Attendee Walkthrough"), allowing them to choose their destination consciously.
  • Parallel Quick Directory: Directly below the cards, a comparative matrix maps out every pillar (Build, Scale, Govern, Optimise) and insight hub, offering 1-click entry into either track.
  • Zero JavaScript Dependency: The gateway is implemented in pure static HTML and semantic CSS variables, ensuring instant load times and complete accessibility.

4. The Universal 1-Click Companion Bridge

While the two reading tracks are segregated for focus, they are never isolated. Every single document carries a context-aware 1-click bridge to its exact counterpart:

This bi-directional linking guarantees that whichever path the visitor took initially, they can cross over to verify implementation details or consult original instructions in a single click.

5. Static Site Engineering & Principle of Least Astonishment

The static publishing architecture satisfies core engineering principles:

  • GitHub Pages Parity: Published directly from the /docs directory with .nojekyll to disable Jekyll processing, guaranteeing that raw SVG diagrams, styles, and relative assets load identically locally and in production.
  • Local Server Parity: Running cd docs && python -m http.server 8080 mirrors production exactly: localhost:8080/ serves the Split-Gateway Portal and localhost:8080/instructor/ serves the instructor curriculum.
  • Theme Persistence: Both tracks share a unified dark/light theme engine adhering to OS preferences with zero flash-of-unstyled-theme (FOUST).
